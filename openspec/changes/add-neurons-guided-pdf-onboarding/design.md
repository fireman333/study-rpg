## Context

`add-neurons-tauri-shell` shipped a desktop resolver that matches a question's source PDF by **exact filename** (`findByNfcName` over the granted folder, comparing the on-disk name to the provenance map's baked `file`). In practice the player obtains PDFs from the publisher's Google Drive, which names files arbitrarily, and macOS stores CJK as NFD — so the downloaded file rarely matches the baked filename and the「看原始詳解」action quietly does nothing. There's also no in-app path to *get* the PDFs or *grant* the folder.

Grilled (Deep) + Codex (`gpt-5.5`) pressure-test. Codex's locked invariant: **"booklet identity is proven by content fingerprint, filename is only a normalized storage convention."** The owner supplied the 44 official 陽明 Google Drive links (104-1 … 115-1 × 醫學一/醫學二). Licensing posture (LOCKED): the project distributes/hosts/mirrors **zero copyrighted bytes**; it only links to the publisher's own public files and reads what the player downloaded.

## Goals / Non-Goals

**Goals:**
- Match local PDFs to booklets by **content**, not filename (kills the Drive-naming + NFC/NFD failure).
- Guide the desktop player to the publisher's official downloads + teach the folder grant, all in-app.
- Add a desktop bug-report category via the CLI-first Supabase path.
- Ship the new app/web icon.

**Non-Goals (separate follow-up changes):**
- **One-click direct-fetch** from Drive (Rust HTTP + confirm-token + hardening) — Codex's checklist is in the grill summary §10.1.
- AI-generating the 5 never-written 詳解.
- Any change to the web (FSA) resolution path or the web app's behavior (beyond the favicon).

## Decisions

### D1 — Fingerprint signal: page count + normalized text hash of pages {1, 2, last}
Per Codex: cheapest reliable signal for ~46 distinct booklets. NOT PDF metadata title (often empty/wrong), NOT filename. A booklet's `fingerprints` = `[ sha256(normText(p1)), sha256(normText(p2)), sha256(normText(pLast)) ]` plus `pageCount` and `expectedSizeRange`. **Match policy**: strong = pageCount + all available text hashes; **weak** = pageCount + ≥2/3 text hashes (tolerates a re-exported PDF); **pageCount-only** → low-confidence, require explicit player confirm (don't silently resolve). `normText` = trim + collapse whitespace + NFC, so it's stable across extraction runs.

### D2 — Fingerprint with the BUNDLED pdfjs (build==runtime engine parity); no new Rust PDF dependency
The hash is only meaningful if the SAME extraction engine produces it at build time and runtime — different engines (PyMuPDF/fitz vs pdfjs) yield different text, so hashes wouldn't match. The app already bundles `pdfjs-dist 5.4.296` (react-pdf). Decision: fingerprint in the **frontend with the bundled pdfjs** at runtime, and build the manifest with the **same pdfjs in Node** at build time. The Tauri Rust side gains only `list_pdf_files_with_stat` (name + size + mtime) and reuses `read_pdf_file` (bytes); all PDF parsing stays in pdfjs.
- *Alternative considered*: a Rust PDF lib (`pdfium-render` / `lopdf` / `pdf-extract`). Rejected — adds a heavy/native dependency AND breaks build/runtime parity unless the build script uses the same lib; pdfjs is already present and gives parity for free.

### D3 — Per-file fingerprint cache (keyed by size+mtime); on-demand + explicit rescan
Reading each candidate PDF's bytes into JS to fingerprint is heavy (up to ~96 MB each). Mitigate: cache `{ fileName → { size, mtime, pageCount, fingerprints } }` device-local (mirrors `folderStore` isolation, never synced). On opening a question, fingerprint files until the target bookletId is found (caching each); a「掃描資料夾」action proactively fingerprints all and refreshes the cache. Recompute a file's fingerprint only when its size+mtime changed.

### D4 — Committed source artifacts (not regenerable in CI)
Two build outputs, COMMITTED like `provenance/question-page-map.json` (CI has no PDFs to regenerate them):
- `fingerprint-manifest.json` — `{ bookletId, canonicalFile, pageCount, fingerprints[], expectedSizeRange }[]`, generated by a new Node+pdfjs script over the owner's `~/Desktop/國考/一階國考/陽明國考考古/` PDFs.
- `booklet-drive-links.json` — `{ bookletId → { driveFileId, viewUrl } }`, parsed from the owner's 44 links (normalize both URL formats `/file/d/<ID>/view` and `uc?export=view&id=<ID>`, and the 104-1醫二 `resourcekey`). `bookletId` = `<year>-<session>-med1|med2`, reconciled with the provenance map's per-question booklet so a question → bookletId → driveUrl.

### D5 — Guided-download UX (desktop-gated)
- **Inline missing-file prompt**: when a mapped question's bookletId isn't resolvable in the folder, the existing `LocalPdfButton` area shows an actionable card: official Drive link (opens in system browser via Tauri shell-open) +「這是哪一份 booklet」+「我下載好了 → 掃描資料夾」. Replaces the current bare file-not-found note on desktop.
- **Global onboarding banner**: shown only on Tauri desktop AND `getStatus() !== 'ready'` (no folder granted). Two steps: 1) download your PDFs (official links) 2) grant the folder. Dismisses on grant.
- **Settings「全部下載」**: a list of all 44 official links for the player who wants everything up front.

## Risks / Trade-offs

- **Scanned / garbled-text booklets** (e.g. 104-2醫一 garbled font, the notext booklets) may not yield clean page text → text hashes unreliable. Mitigation: those bookletIds fall back to `pageCount + expectedSizeRange` as a low-confidence match → require explicit player confirm (D1). Validate against all 46 real PDFs at apply; record which booklets are text-fingerprintable vs size-only.
- **Build/runtime hash parity** → must pin the SAME pdfjs version + identical `normText` for build script and runtime, and unit-test that the build manifest's hash for a sample PDF equals the runtime hash. A pdfjs bump must regenerate the manifest.
- **First-scan I/O** (reading ~1 GB across 46 PDFs into JS) → bounded by the per-file cache (once each) + lazy on-demand; surface progress in the「掃描」action. Acceptable on desktop.
- **Drive link rot** (publisher changes a file ID) → `booklet-drive-links.json` is committed + easily patched; a dead link degrades to「請到 陽明 頁面找這份」rather than breaking.
- **`supabase db push` DB connection** → needs the CLI to reach the DB (pooler/password). Owner authorizes; fallback = generate the SQL and the owner applies it (dashboard) if the CLI can't connect. Either way the migration file is committed.
- **Change size** → this bundles a meaty resolver rewrite + UI + a backend migration + an asset swap. Honoring the owner's「one change」call; tasks.md groups them so apply can pause cleanly between groups. If apply reveals it's unwieldy, split the bug-report migration out as `add-neurons-desktop-bug-category`.
