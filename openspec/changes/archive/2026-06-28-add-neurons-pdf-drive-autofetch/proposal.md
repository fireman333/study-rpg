## Why

The web 「看原始詳解 PDF」 feature today relies on the File System Access API (player grants a local folder) plus the player manually downloading 46 陽明 booklets. That works **only on Chromium desktop** — Safari and every mobile browser get nothing — and imposes a multi-step download-then-grant onboarding. We have **validated** a path that delivers the same page-anchored original-PDF view on web **and mobile** with **zero user action**: the browser fetches each booklet directly from the publisher's official Google Drive via the Drive API (CORS-enabled, referrer-restricted key) into a client-local cache. (Validation: a referrer-restricted key returns `HTTP 206 / application/pdf / %PDF-` for a public file from the `med-study-rpg.com` origin; requests without the referrer are blocked.)

## What Changes

- **BREAKING (web delivery mechanism)**: Replace the FSA folder-grant source with **browser-direct auto-fetch from the Google Drive API** (`GET .../files/{id}?alt=media&key=…`), keyed by the already-committed booklet→Drive-file-ID map. Bytes flow publisher-Drive → browser → device cache; the app's own infrastructure never holds, hosts, mirrors, or serves them.
- **On-demand fetch**: a booklet is fetched only when the player opens a mapped question that lives in it; the bytes are cached so later opens are instant. A Settings toggle **「全部下載供離線」** fetches all 46 booklets in one action.
- **Cache layer**: cached PDF bytes live behind a small swappable byte-store interface (`get` / `put` / `delete` / `list`); v1 = **Cache API** (OPFS + pdf.js range-read deferred to a later change — OPFS only pays off once the viewer does partial reads, which it does not yet). **No new Dexie table, no schema bump**: `cache.match` answers "is this booklet cached?", `cache.keys` lists cached booklets, the 「全部下載供離線」 preference rides the existing key-value `meta` store, and no LRU is needed (eviction is a harmless re-fetch). 20–96 MB PDFs are **never** stored in IndexedDB.
- **Remove** the folder-grant flow, the `PdfOnboardingBanner` + `BookletDownloadList` download-teaching UI, and CJK filename matching — none are needed when fetching by Drive ID. Existing FSA-granted users (incl. the owner) move to auto-fetch transparently; the old device-local folder-handle store becomes dead.
- **Mobile + Safari now work** (it is fetch + pdf.js, no FSA dependency). The provenance action is hidden only for **unmapped** questions or on a **hard fetch failure** (Drive 404 / quota / link-rot), where a non-blocking message surfaces the official Drive link as fallback (No Silent Errors).
- **Re-scope the zero-bytes guarantee** from "zero copyrighted bytes" to **"zero APP-hosted bytes"**: the app still bundles / hosts / mirrors / serves no PDF bytes; the browser fetches from the publisher's own official Drive, cached only on the player's device.

### Modified Capabilities
- `neurons-explanation-pdf-provenance`: the source-resolution mechanism changes from FSA folder-grant to **browser-direct Drive-API auto-fetch + client byte-cache**. Specifically — the "open at mapped page" requirement now resolves the source by Drive fetch+cache (the docked pdf.js panel is unchanged); the "folder grant persists" and "CJK filename matching" requirements are **REMOVED**; "graceful degradation" is updated (the feature now runs on mobile/Safari, hidden only on unmapped-question or fetch-failure); the "zero copyrighted bytes" requirement is re-scoped to **zero app-hosted bytes**. New requirements cover: (a) on-demand-plus-offline-all fetch behavior; (b) the swappable byte-cache store; (c) **booklet→Drive-ID resolution via a stable `bookletKey`** — the question→{page} map references a stable booklet identity (PDF filename is display/debug only), resolved to `driveFileId` (+ optional `resourceKey`) via the committed booklet manifest; (d) fetch error handling (offline-but-not-cached, transient `5xx` retry, `403/429` quota surfaced as non-blocking degradation, all with the official Drive link as fallback); (e) a privacy/security note (the browser sends Drive file IDs + a referrer-restricted **non-secret** API key to googleapis.com; the key is abuse-limited by referrer + quota, NOT secret, so only public/shared Drive files are addressable and access rests on Drive sharing permissions); and (f) **responsive panel presentation** — the docked, content-reflowing panel is now scoped to wide viewports, and narrow (phone) viewports present a full-screen overlay instead (the resize handle hidden), so the feature is actually usable on the mobile/Safari path this change enables.

## Impact

- **Code (`apps/neurons-tw/`)**: `src/platform/` web branch rewritten (`getStatus` / `grantFolder` / `openExplanation` → Drive fetch + cache; `folderStore` removed); `provenance.ts` gains file→Drive-ID lookup via `booklet-drive-links.json`; new byte-cache module (Cache API behind a swappable `get/put/delete/list` interface — **no Dexie table / no schema bump**); `LocalPdfButton` / `useLocalPdfAvailable` re-gated (available = mapped ∧ (cached ∨ fetchable)); **remove** `PdfOnboardingBanner` + `BookletDownloadList` from `App.tsx`; Settings panel gains the 「全部下載供離線」 toggle. `PdfDocumentView` (the page renderer) is unchanged; `PdfPanelHost` + `PdfPanelProvider` gain a **responsive layout** — docked side panel on desktop, full-screen overlay (`100vw × 100dvh`) on narrow (< 768px) viewports — since the docked side-by-side reflow is unusable on phones (panel floor 360px would crush content to a sliver).
- **Config**: new `VITE_GDRIVE_API_KEY` in `apps/neurons-tw/.env.local` (gitignored). ⚠️ per-worktree: it must ALSO live in the deploy worktree `~/coding-scratch/study-rpg/apps/neurons-tw/.env.local`, or `pnpm deploy:cf` silently bakes a build with no key.
- **Data**: reuses the committed `packages/content-neurons-tw/provenance/booklet-drive-links.json` (46 entries: `bookletKey` → `driveFileId` [+ `resourceKey` in `viewUrl`]) as the booklet manifest. The provenance-map builder is extended so each question entry carries (or resolves to) a stable `bookletKey` → `driveFileId` (+ `resourceKey?`), so the runtime fetches by Drive ID, not by filename (filename stays display/debug only). Edge: `104-1-醫學二` is a legacy `0B…` Drive ID with a `resourceKey` → its API call needs an extra `X-Goog-Drive-Resource-Keys: {id}/{rk}` header; the other 45 are plain.
- **Dependencies**: none new (Drive REST via `fetch`; existing `react-pdf`).
- **Out of scope**: the desktop Tauri shell (`neurons-tauri-shell` capability incl. its onboarding-banner / folder-grant / guided-download requirements) is removed in a **separate follow-up change** — now clearly justified (web auto-fetch delivers page-anchored PDF on all desktop browsers + mobile, leaving Tauri no residual unique value), but kept out of THIS change so web auto-fetch lands with a clean diff first. Cloud sync / R2 / economy / Dexie game schema are untouched (this is purely the PDF delivery/presentation layer).
- **Migration**: existing FSA-granted users (incl. the owner) need no action — auto-fetch supersedes the grant; the now-dead `neurons-local-pdf` folder-handle IndexedDB store can be cleaned up opportunistically.
