## Context

The neurons-tw 一階 corpus is produced by the self-contained reconcile toolchain in `packages/content-neurons-tw/reconcile/` (built 2026-05-30, "考選部權威化"):

```
manifest.json (考選部 download coords)
  → download_all.py  (curl 考選部 試題/標準答案/更正答案 PDFs → reconcile/pdf/)
  → parse_moex.py    (考選部 試題: N. + A./B./C./D.;  標準答案: full-width letter grid)
  → reconcile_all.py reconcile_year(y):  per (book,qNum): qNum-direct match vs 陽明 pool
                       (sim≥0.55) → content-sim fallback → gap(no 陽明)→ empty 詳解
  → reconcile.py     clean_explanation() strips furniture; parse_corrections() → acceptedAnswers
  → finalize.py      OLD_106_1 manual subject blocks + 微免 split → data/medexam-reconciled/*.json
```

`reconcile_year` sources 陽明 explanations from `YM_ROOT/<book>/<subject>/<year>-<sess>.md` (the `_extracted/` per-subject markdown), keyed by (book, qNum). Subjects from 考選部 試題 are not labelled per-question; for the lone old-grouping paper (106-1) `finalize.py` overrides subject with hand-confirmed contiguous blocks (`OLD_106_1`). Modern years (107–114) inherit subject from the qNum-aligned 陽明 subject file.

Current state verified for this change:

Format is heterogeneous: 104-1/105-1 use `Ans：(X)` (≈100 markers/book); **104-2/105-2 use a different layout** (0 `Ans：` markers — different answer label / section style).
- **115-1**: 考選部 official PDFs supplied (`~/Downloads/115020_{1301,2301}.pdf` = 醫一/醫二 試題 100 Q each, parse_moex-compatible; `115020_MOD1301.pdf` = 醫一 更正答案 with Q66 多選給分 + Q95 一律給分). **No 陽明 詳解 exists**, and the **醫二 標準答案 is missing**.

## Decisions

### D1 — 104/105 陽明 詳解: extract whole-paper PDFs into `_extracted/` markdown first, then reuse `reconcile_year`
The reconciler reads 陽明 explanations from `_extracted/<book>/<subject>/<year>-<sess>.md`. Rather than rewrite the reconciler to read raw 陽明 PDFs, a new `parse_ym_104_105.py` parses each whole-paper PDF → per-question `{qNum, stem, answer, explanation}` (global qNum 1..N per book, matching how the 陽明 PDF numbers) and writes `## Qn` markdown into `_extracted/`. The reconciler then matches by qNum-direct exactly as for 106–114.
- **Why**: minimizes reconciler changes; keeps `_extracted/` as the canonical 陽明 store; subject-folder placement is non-critical because `finalize.py` OLD-block override sets the canonical subject for old-grouping years anyway.
- **Three formats (confirmed Phase 0)**: (a) inline `Ans：(X)` — 104-1, 105-1; (b) structured `題目/答案/科目/答題要訣/參考詳解` — 105-2; (c) **104-2 醫一/醫二 — scrambled ToUnicode, NOT losslessly re-decodable (subset font's `cmap` stripped; embedded `DFKaiShu-SB-Estd` cut ≠ installed `DFKaiShuW5` so glyph-outline match is 0%; poppler drops CJK). Pages render clean (vector outlines intact) → rendered @300dpi + macOS Vision OCR (`ocrmac`, zh-Hant), feeding the SAME structured parser as (b). OCR validated high-quality 2026-06-03.** Explanation text only — 題幹/選項/答案 come from 考選部.
- **Alternative rejected**: teach `reconcile_all.py` to read raw PDFs directly → couples reconcile logic to 陽明 PDF quirks, harder to reuse `clean_explanation` keyed flow.

### D2 — 104/105 are 舊分組: hand-confirmed contiguous subject blocks (`OLD_104_1` … `OLD_105_2`)
Mirror `OLD_106_1`. Boundaries are read off each 陽明 PDF's own subject section headers (the 陽明 詳解 IS organized by subject), proposed to the owner, and hardcoded in `finalize.py`. `finalize.py`'s loop + `subject_NNN` lookup generalize from a single `OLD_106_1` to a per-(year,session) table.
- **Why**: pre-106 一階 papers distribute subjects differently from the modern template; auto-classification on old papers is unreliable. Manual blocks are the proven 106-1 approach.
- **Checkpoint**: subject-block table is owner-confirmed before bake (one of the guided stops).

### D3 — 115: new AI-generated-explanation path, provenance-tagged + verified + flagged
115 has 考選部 試題/答案 but no 陽明. A new `generate_115.py` (a) parses 考選部 試題 (`parse_moex.parse_questions`) + 標準答案/更正 (`parse_answers` / `parse_corrections`), (b) for each Q calls **Gemini CLI with web search** given stem + options + the authoritative correct answer, producing a 繁中 explanation in the same shape as cleaned 陽明 詳解, (c) records provenance, (d) runs a **second-pass verification** (the explanation must endorse the authoritative answer; a spot adversarial/OE check on a sample + all "uncertain" self-reports), (e) emits a **low-confidence flag list** for owner review.
- **Provenance**: 115 questions carry `explanationSource: 'ai-generated'` and a distinct `sourceCredit` ("考選部（試題與標準答案）+ AI 生成詳解（Gemini，未經陽明審定）"). The neurons UI MAY surface an "AI 生成詳解" note (UI wiring deferred; data carries the flag now). content-pack-contract attribution stays satisfiable.
- **Answer authority**: Gemini is given the 考選部 answer and asked to explain it, never to pick the answer — eliminates the "AI guesses wrong key" failure mode. If Gemini's reasoning contradicts the authoritative answer, the item is auto-flagged.
- **Why Gemini CLI + search (not OE-only)**: mirrors the established 二階 generation path the owner asked for; web search grounds basic-science facts. OE is used in the verification pass for a sample, not as the primary generator (OE is clinical-leaning; 醫一 basic-science coverage is thinner).
- **Per global rule**: medical/neuroscience facts in generated explanations are evidence-grounded where the verification pass touches them; the low-confidence flag is the human gate.

### D4 — 115 subject assignment: classifier + contiguous-block smoothing + owner spot-check
Modern 一階 papers block subjects contiguously but 考選部 試題 carries no per-Q subject label, and there is no 陽明 file to align against. Run `subject_clf.py` (trained on 34 modern papers) over the 115 stems, smooth to contiguous runs (subjects don't interleave), and have the owner spot-check the ~4 boundary rows per book.
- **Alternative rejected**: pure manual blocks (115 is modern, classifier is reliable here — manual only for boundaries); Gemini-classified subject (adds a second AI dependency for a deterministic-ish task).

### D5 — Additive-only, new ids, no orphan/migration concern
All new ids are brand-new exam coordinates (`{year}-{sess}-{book}-{subject}-Q{n}`); no existing SRS card / bookmark / variant references them. No Dexie `.version()` bump, no R2 bundle schema bump, no sync change. Rollback = `git revert` the regenerated JSON.

### D6 — 考選部 fetch via existing `download_all.py` + `find_cs.py`
Extend `manifest.json` with 104-1/104-2/105-1/105-2/115-1 entries. Coordinates (`code`/`c`/`s1`/`s2`) found with `find_cs.py` (PDF-header brute-force) — 考選部 internal codes differ per year. For 115, the owner already has 試題 + 醫一 更正; only the 醫二 標準答案 is fetched. File-fetch fallback order per global rule (free 考選部 endpoint first; Chrome MCP only if blocked).

## Risks / Trade-offs

- **104-2 / 105-2 陽明 PDFs use an unknown/alternate text layout (0 `Ans：` markers); 104-2醫一 had garbled page-0 bytes** → Phase 0 inspects all 8 PDFs per-format before committing the extractor; if any page is CID-garbled (high char count but unreadable), fall back to per-page OCR for that PDF only. Extraction correctness is verified by sampling.
- **115 AI explanations may be medically wrong / confidently-wrong-rationale** → answer is authoritative-given (not AI-chosen); verification pass auto-flags reasoning that contradicts the key; low-confidence list goes to owner; this is the explicit owner-chosen "generate + second-pass verify + flag" depth, not blind ship.
- **115 subject misclassification → wrong neuron family** → classifier + contiguous smoothing + owner boundary spot-check.
- **Larger corpus (3600→~4200) breaks hardcoded assumptions** (achievement thresholds, subject mastery coverage %, any `/3600`-style denominator) → Phase 5 audits for hardcoded corpus/subject counts and updates or confirms each. (Memory notes a prior `/55`,`/77`,`/110` denominator cleanup pattern — same vigilance.)
- **Shared neurons worktree with another active session** → explicit per-file `git add`, `git diff --cached --name-status` before every commit, watch `git reflog`; never `git add -A`. Commit only at guided checkpoints when the tree is in a known state.
- **考選部 download coords wrong / site change** → `find_cs.py` validates via PDF header; manual download fallback if automation fails.

## Migration Plan

Purely additive content regeneration — no deploy-time migration. Sequence (guided, with owner checkpoints ⏸):
1. **Phase 0** — inspect 8 陽明 PDFs (per-format), find 考選部 coords for the 5 papers, confirm question counts. ⏸ report findings.
2. **Phase 1** — `parse_ym_104_105.py`: extract 8 陽明 PDFs → `_extracted/` markdown; sample-verify.
3. **Phase 2** — extend `manifest.json`; `download_all.py` 104/105 考選部; reconcile; propose `OLD_104/105` subject blocks. ⏸ owner confirms subject blocks.
4. **Phase 3** — 115: parse 考選部 試題/答案, fetch 醫二 標準答案, classify subjects. ⏸ owner spot-checks subject boundaries.
5. **Phase 4** — `generate_115.py`: Gemini+search explanations + verification pass + low-confidence flag list. ⏸ owner reviews flagged items.
6. **Phase 5** — extend `finalize.py`; regen `data/medexam-reconciled/*.json`; `pnpm --filter @study-rpg/content-neurons-tw build`; `copy-content.mjs`; audit corpus-size-dependent features; Chrome MCP app smoke (new years load, subject filter, explanation render incl. AI-note).
7. **Phase 6** — `/opsx:verify` + explicit-add commit + (owner) push. No infra/owner-run external steps.

**Rollback**: `git revert` the JSON regeneration commit; corpus returns to 3600. No data/schema rollback needed.
